# Get started with the nRF91 AT Host Application

This guide takes you from an nRF54LM20B DK and an nRF9151 DK to a device that reports its location to nRF Cloud. The application runs on the nRF54LM20B DK and drives the nRF9151 DK, which runs the Serial Modem firmware, with AT commands. The Serial Modem onboards itself to nRF Cloud and does all cloud communication, so there are no certificates to install on the host.

![This guide covers steps 3 to 6: Set up the hardware, Build and flash, Connect to nRF Cloud, and Verify](../images/getting-started-steps-3-6.svg)

Before you start, complete [Step 1: Choose your application](index.md#step-1-choose-your-application). To build from source, also complete [Step 2: Set up the repository and toolchain](setup.md).

## Step 3: Set up the hardware

The hardware setup is the same as for the PPP Host Application on the nRF54LM20B DK. The nRF7002-EB II is not used.

1. Configure the nRF9151 DK, flash the Serial Modem firmware, and configure the nRF54LM20B DK, as described in steps [3.1](ppp-nrf54.md#31-configure-the-nrf9151-dk-in-board-configurator) to [3.3](ppp-nrf54.md#33-configure-the-nrf54-dk-in-board-configurator) of the PPP guide. Use Serial Modem v2.0.0 or later, which has the provisioning commands.
1. Wire the DKs as in [3.4 Wire the DKs together](ppp-nrf54.md#34-wire-the-dks-together), using the **nRF54LM20B DK** table. The application does not use RI, so that wire is optional.
1. Run `nrfutil device list` and note the nRF54LM20B DK's **VCOM0** port. That is the host console.

**Checkpoint:** Both DKs are powered, and the eight wires (or seven, without RI) are connected.

## Step 4: Build and flash

1. Flash the host firmware. Choose one of the following options:

    - **Build from source:** Run the following commands inside the toolchain shell (step 2.4 in [Set up the repository and toolchain](setup.md)), from `smha-workspace/project`:

        ```shell
        cd applications/91m1_at
        west build -b nrf54lm20dk/nrf54lm20b/cpuapp/ns -p
        west flash
        ```

        If flashing fails because the device has never been programmed with this application or is read-back protected, run `west flash --recover` once. This application stores no cloud credentials on the host, so there is nothing to lose.

    - **Pre-built firmware:** Download the `91m1_at-nrf54lm20b-*` zip from the [latest release](https://github.com/nrfconnect/ncs-serial-modem-host-applications/releases), extract it, and flash `merged.hex`. See [Release artifacts](../release-artifacts.md) for what the zip contains.

        ```shell
        nrfutil device recover --serial-number <host_dk_serial_number>
        nrfutil device program --firmware merged.hex --serial-number <host_dk_serial_number>
        nrfutil device reset --serial-number <host_dk_serial_number>
        ```

1. Open a serial terminal at 115200 baud on VCOM0 of the nRF54LM20B DK and reset the DK.

**Checkpoint:** The console logs the following once LTE is registered:

```text
<inf> network: Network connected
<inf> cloud: Device UUID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
<inf> cloud: Provisioning started
```

## Step 5: Connect to nRF Cloud

A new device is not claimed in nRF Cloud yet, so the provisioning service refuses it. The console then logs the device's attestation token, which you use to claim it:

```text
<wrn> cloud: Device not claimed, claim it in nRF Cloud with the attestation token
<inf> cloud: Attestation token: 2dn3hQFQUEI0UTc3SWeAN...
```

1. In nRF Cloud, go to **Fleet** > **Devices**.
1. Click **+ Add New Devices**.
1. Select the nRF91 Series and paste the attestation token from the console.
1. Review and confirm.

The application retries provisioning every 60 seconds. On the next attempt the Serial Modem installs its nRF Cloud credentials. It takes LTE offline for that, so the console logs `Network disconnected` and `Network connected` in between.

**Checkpoint:** The console logs the following:

```text
<inf> cloud: Provisioning done
<inf> main: Cloud connected, first sync in 5 s
```

The device, named after its UUID, appears in the device list.

## Step 6: Verify

The application runs a **cloud synchronization** 5 seconds after it connects to nRF Cloud, and then every 10 minutes (`CONFIG_APP_SYNC_BOOT_DELAY_SECONDS` and `CONFIG_APP_SYNC_INTERVAL`). Each synchronization requests a location fix from the Serial Modem.

1. Check that the console logs the location result:

    ```text
    <inf> location: Location: 63.420824,10.443289 Uncertainty: 344m Method: Multicell
    ```

    The line only appears after nRF Cloud has resolved the cell measurements, so it confirms the whole round trip. If the cellular request fails, the application runs a GNSS fix instead, which needs a clear view of the sky.

1. In nRF Cloud, go to **Fleet** > **Devices** and click your device. The device page shows the location fixes.

To try the Serial Modem commands by hand, use the `at` shell command. For example:

```text
uart:~$ at AT#XNRFCLOUD?
#XNRFCLOUD: 1,1,16842753,"xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
OK
```

If no location shows up, see [Troubleshooting](../applications/91m1_at/README.md#troubleshooting).
