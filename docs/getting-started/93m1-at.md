# Get started with the nRF93M1 AT Host Application

This guide takes you from an [nRF93M1 DK](https://www.nordicsemi.com/Products/Development-hardware/nRF93M1-DK) to a device that sends its location and battery level to nRF Cloud. The application runs on the DK's nRF54L15 host. The on-board nRF93M1 modem talks to nRF Cloud with its own built-in client, and the host drives it with AT commands.

```mermaid
flowchart LR
    HW["1 Set up the hardware"] --> BF["2 Build and flash"]
    BF --> Cloud["3 Connect to nRF Cloud"]
    Cloud --> Verify["4 Verify"]
    Verify --> Next["5 Next steps"]
```

Before you start, complete the [Before you begin](index.md#before-you-begin) checklist. To build from source, also complete [Set up the repository and toolchain](setup.md).

## Step 1: Set up the hardware

The host and the modem are on the same DK, so there is no wiring.

1. Connect the nRF93M1 DK to your computer over USB and turn it on.
1. Run `nrfutil device list` and note the DK's serial number and its **VCOM0** port. VCOM0 is the host console (`uart20`). On macOS the port looks like `/dev/cu.usbmodem*`, on Linux like `/dev/ttyACM*`, and on Windows like `COM*`.
1. For battery reports, connect a battery to the DK. Without one, the application still runs but skips the battery message.

**Checkpoint:** `nrfutil device list` shows the nRF93M1 DK.

## Step 2: Build and flash

Run the following commands inside the toolchain shell (see [Start the toolchain shell](setup.md#start-the-toolchain-shell)), from `smha-workspace/project`:

```shell
cd applications/93m1_at
west build -b nrf93m1dk/nrf54l15/cpuapp/ns -p
west flash
```

If flashing fails because the device has never been programmed with this application or is read-back protected, run `west flash --recover` once. This application stores no cloud credentials on the host, so there is nothing to lose.

**Using pre-built firmware instead:** Download the `93m1_at-nrf93m1-*` zip from the [latest release](https://github.com/nrfconnect/ncs-serial-modem-host-applications/releases), extract it, and flash `merged.hex`:

```shell
nrfutil device recover --serial-number <dk_serial_number>
nrfutil device program --firmware merged.hex --serial-number <dk_serial_number>
nrfutil device reset --serial-number <dk_serial_number>
```

See [Release artifacts](../release-artifacts.md) for what the zip contains.

**Checkpoint:** Open a serial terminal at 115200 baud on VCOM0 and reset the DK. When the modem has attached to the network, the console logs the following:

```text
<inf> main: Network connected, first sync in 5 s
```

## Step 3: Connect to nRF Cloud

The modem is its own nRF Cloud client, so you claim the modem in your nRF Cloud account. There are no certificates to install on the host. The commands below use the application's `at` shell command on the console.

1. In nRF Cloud, go to **Fleet** > **Devices**.
1. Click **+ Add New Devices**.
1. Select **nRF93M1** and click **Continue**.
1. Run the two AT commands that nRF Cloud shows, through the `at` shell command, to get the device UUID and a registration token (JWT):

    ```text
    uart:~$ at AT%DEVICEUUID
    %DEVICEUUID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
    OK
    ```

    ```text
    uart:~$ at AT%REGJWT=<team-id>
    %REGJWT: <jwt>
    OK
    ```

1. Paste the UUID and JWT back into nRF Cloud to finish claiming the device.
1. Review and confirm.

**Checkpoint:** The device appears in the device list within a few seconds. The new nRF Cloud UI does not show a connection status. Instead, the device's **Last seen** time updates once the modem first talks to nRF Cloud.

If the console logs `modem_at: CoAP response: 4.01 Unauthorized (device may not be onboarded to nRF Cloud)`, nRF Cloud rejected the modem. Finish the claiming steps and check that the device is listed under your team.

## Step 4: Verify

The application runs a **cloud synchronization** 5 seconds after the network connects, and then every 10 minutes (`CONFIG_APP_SYNC_BOOT_DELAY_SECONDS` and `CONFIG_APP_SYNC_INTERVAL`). Each synchronization requests a location fix and reports the battery level. Press **Button 1** on the DK, or run `button 1`, to start one right away.

### On the device

Each synchronization logs the location result and the battery report:

```text
<dbg> location: Location: 63.421,10.437 Uncertainty: 25m Method: Wi-Fi
<dbg> cloud: Battery percentage reported: 87%
```

The location line only appears after nRF Cloud has answered, so it confirms the whole round trip. `Method` is the source nRF Cloud used, which can differ from the requested one when several are allowed. The battery line means the modem accepted the message for sending.

To test the cloud path by hand, send a message or request a location with the `at` shell. Single quotes keep the JSON double quotes intact:

```text
uart:~$ at 'AT%NRFCLOUDMESSAGE={"appId":"TEST","data":"hello"}'
%NRFCLOUDMESSAGE: SENT
OK
uart:~$ at AT%NRFCLOUDLOCATION=1,1
OK
<dbg> location: Location: 63.421,10.437 Uncertainty: 1200m Method: Single-cell
```

### In nRF Cloud

In the new UI, go to **Fleet** > **Devices** and find your device. Its **Last seen** time updates after each synchronization.

> [!NOTE]
> nRF Cloud is moving to a Memfault-integrated experience. For now, location fixes and messages are only visible in the **legacy nRF Cloud portal**. After logging in at [nrfcloud.com](https://nrfcloud.com), open the legacy app using the link in the **bottom left corner** of the new UI.

1. In the legacy app, open **Device Management** > **Devices** and click the device ID. The device ID is the modem UUID from `AT%DEVICEUUID`.
1. The map on the device page shows the location fixes from each synchronization.
1. The **Terminal** card shows the `BATTERY` device messages, one per synchronization.
1. To load older messages, click the clock icon, select a time range, and click **Get Data**.

The same data is available from the [nRF Cloud REST API](https://api.nrfcloud.com/). Get `<api_key>` in the legacy app by selecting your team, then the **burger menu** > **User Account** > **Team Details**. See [Managing tokens and keys](https://docs.memfault.com/docs/legacy-nrfcloud/tokens-and-keys) for more details.

```shell
curl -H "Authorization: Bearer <api_key>" \
  "https://api.nrfcloud.com/v1/messages?deviceId=<device_uuid>&pageLimit=10"
curl -H "Authorization: Bearer <api_key>" \
  "https://api.nrfcloud.com/v1/location/history?deviceId=<device_uuid>&pageLimit=10"
```

If no location or battery data shows up, see [Troubleshooting](../applications/93m1_at/README.md#troubleshooting).
